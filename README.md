# Android Course Manager（课程管理与工资统计）

一款基于 **Python + Kivy + SQLite** 的课程记录与工资统计工具，面向日常授课记录管理。应用以本地数据为主，支持离线记录课程，并提供课程查询、日历查看、工资计算、Excel 导入导出和本地备份等功能。

> 项目当前以 Android 手机端使用为主要目标。应用数据保存在本机；卸载应用前请先导出或备份数据。

## 主要功能

### 1. 课程记录

- 录入课程日期、开始和结束时间、课程类型、科目、年级、学生人数、学生姓名、授课地点及课时等信息。
- 查询和管理已保存的课程记录。
- 支持课程模板，便于重复录入相似课程。
- 日历页面按日期查看课程安排。

### 2. 课时与工资统计

- 按课程记录计算课时工资，并汇总固定工资项目。
- 固定工资项目目前包括：基本工资、晚托、全勤和教师资格证补贴。
- 年级课时单价规则：1–6 年级 30 元，7–9 年级 35 元，10–12 年级 40 元。
- 每课时按 40 分钟计算。
- 课时工资基础计算规则：

  `总课时 × (年级单价 + (学生人数 - 1) × 10) × 2 / 3`

- 周末及配置的节假日按程序内既定规则处理；符合条件的 17:00 后课程适用三倍课时规则。
- 加班明细记录日期、时间、实际加班课时、折算课时及加班增加工资。加班增加工资作为明细展示，已经包含在按折算课时计算的课时工资中，不应再次叠加到工资总额。

### 3. 学生信息费

- 同一学生同一自然周（周一至周日）只计收一次信息费。
- 同一周内跨校区上课时按学生去重，信息费归属该学生本周第一次上课的校区。
- 跨月自然周按本周第一次上课日期归属月份，不拆分、不重复收费。
- 学生姓名支持中文逗号、顿号、英文逗号、分号及换行分隔。

### 4. 校区与分类汇总

工资统计结果包含校区课时、课时费、学生信息费和校区合计，也可按年级、课程类型等维度查看汇总。

### 5. Excel 与数据备份

- 导出全部课程记录为 Excel。
- 从 Excel 导入课程记录，采用追加方式，不覆盖已有记录；完全相同的记录会跳过。
- 导出工资统计明细。
- 生成本地 JSON 数据备份，并支持从 JSON 备份恢复。
- 支持检查 GitHub Releases 中的软件更新；更新检查不会自动安装新版本。

## 项目结构

项目主要模块如下（以仓库中实际文件为准）：

| 文件/目录 | 作用 |
|---|---|
| `main.py` | Kivy 应用入口、页面布局、交互与页面导航 |
| `database.py` | SQLite 数据库访问、课程记录的增删查改 |
| `calculations.py` | 课时、工资、加班和学生信息费等业务计算 |
| `exporter.py` | Excel 导入、课程及工资数据导出 |
| `updater.py` | 应用版本信息及 GitHub Releases 更新检查 |
| `tests/` | 自动化业务规则测试 |
| `fonts/` | 中文字体资源（如项目中提供） |
| `assets/` | 标题字体等界面资源（如项目中提供） |
| `run_tests.sh` | 语法检查与单元测试脚本（如项目中提供） |

## 运行环境

- Python 3
- Kivy
- SQLite（Python 标准库自带 `sqlite3`）
- Excel 读写所需依赖以项目的 `exporter.py` 和依赖配置文件为准
- Android 打包通常使用 Buildozer，并需要可用的 Android SDK/NDK 构建环境

建议在项目虚拟环境中安装依赖。若仓库提供 `requirements.txt`，可执行：

```bash
python -m pip install -r requirements.txt
```

若没有依赖清单，请先检查项目的 `buildozer.spec`、`exporter.py` 及其他模块，再按项目配置安装依赖；不要直接把桌面开发环境的所有包复制到 Android requirements 中。

## 本地运行

在项目根目录、已安装 Kivy 及项目依赖的 Python 环境中执行：

```bash
python main.py
```

部分桌面系统可能需要额外配置 Kivy 图形环境。Android 端请使用项目配置的打包流程。

## 自动化测试

如果项目根目录存在 `run_tests.sh`，在 Linux / WSL 项目根目录执行：

```bash
chmod +x run_tests.sh
./run_tests.sh
```

也可以直接运行 unittest 测试：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

测试应在项目虚拟环境中执行。修改工资或课时规则后，建议先运行全部测试，再进行手机端回归验证。

## Android APK 构建

Android 打包参数由仓库中的 `buildozer.spec` 决定。若项目已配置 Buildozer 且构建环境安装完成，可在项目根目录尝试：

```bash
buildozer android debug
```

首次构建通常需要下载 Android 构建组件，耗时较长，并要求网络及系统依赖正常。构建成功后，APK 通常位于 `bin/` 目录；具体文件名以构建输出为准。

发布或安装更新版本时：

1. 先确认测试通过，并在真实 Android 设备上检查主要功能。
2. 安装更新前先生成 JSON 备份，或导出课程 Excel。
3. 更新安装时不要先卸载旧版本，以免应用私有目录中的本地数据被删除。
4. 保留版本号、更新说明和对应 APK，便于回溯。

## 数据安全与注意事项

- 课程数据默认保存在应用本地数据库中，不应把“重新安装后数据一定保留”作为前提。
- 更换手机、清除应用数据或卸载应用前，请先生成 JSON 备份，并将备份文件复制到安全位置。
- 从备份恢复前，建议先对当前数据再次备份。
- Excel 导入是追加操作；导入前请确认文件内容，避免加入不需要的历史记录。
- 工资结果依赖课程日期、时间、年级、学生人数、学生姓名和校区等原始信息，录入时请核对准确性。

## 开发与修改建议

1. 先备份当前可正常运行的代码和手机数据。
2. 优先修改对应模块，避免同时改动数据库结构和工资算法。
3. 修改后运行完整单元测试。
4. 再进行桌面启动检查和 Android 手机端回归测试。
5. 涉及数据库字段变更时，应同时考虑旧版本数据库的兼容与迁移。

## 版本与许可

应用版本号由 `updater.py` 管理。项目的代码许可、作者信息及 GitHub 仓库地址应以仓库实际发布信息为准；在这些信息明确前，不在此处虚构许可或仓库链接。
